F1 — FrameGround the thesis in the source paper's own estimates & assumptionsdon't borrow the result — borrow the load-bearing assumption
Reusable principle

Separate what a method derives (robust) from what it assumes (fragile)

Before improving a strategy, inventory its inputs by type: estimates (fit from data), ex-ante values (knowable at decision time), and expectations (idealizing assumptions). Rank them by leverage on realized P&L. The biggest opportunity is almost always where the paper itself admits "no theory" — that is the fragile load-bearing joint, not the elegant closed form.
Decision gate: which 3 inputs, if improved, move performance most? — and which are merely elegant but inert?
Case study — Martin (2023): shape is robust, location is fragile
Three highest-leverage inputs selected: ex-ante vol σ̂ (enters twice, multiplicatively), expected return µ (zero-theory, pure fit), and the backtested Sharpe used to pick activation params (selection-prone). Skewness κ₃ was set aside — Martin proves it is a robust design property of the weights' signs, not a fragile estimate.

What the framing produced

Martin's machinery for the shape of returns (2nd/3rd moments, closed-form term-structure of skew) is Rolls-Royce-grade and robust. His machinery for the location (does it make money?) is, by his own §4.4 admission, pure empiricism. The biggest win is therefore at the signal→position specification, not the vol estimate — vol is a well-solved estimand (incremental upside), whereas the static/uniform activation spec is where alpha lives or dies (order-of-magnitude upside).

Why this matters for the rest

The whole session's target was set here: lift Martin's static constants to state-dependent functions while preserving his positive-skew style constraint (Eq. 20). "Keep the engine, replace the handle." Every later stage is downstream of this single framing call.
F2 — LocateFind the single weak point with the highest "fragility × dependence × upside"and check whether AI/RL actually helps it
Reusable principle

Sensitivity ≠ upside. Target the joint that is fragile, load-bearing, and has order-of-magnitude headroom

A high-sensitivity input (small error → big P&L swing) is not the same as a high-upside one (fixing it unlocks a step-change). Pick the intersection. Then sanity-check whether your fashionable tool (here: reinforcement learning) actually addresses it — often the honest answer is "it speeds adaptation but cannot manufacture invariance."
Decision gate: is the chosen tool solving the real bottleneck, or decorating it?
Case study — RL helps adaptation, not invariance
2025–26 literature read: RL's structural appeal (end-to-end size learning, risk-aware reward) is real, but "time-consistent predictive power" is an OOD problem RL is not built for. Distributional RL is the one branch that maps onto Martin's skew program.

The pivot to López de Prado

Asking "what would add the most value?" surfaced three LdP tools: (1) meta-labeling (separate side from size via the Triple-Barrier Method), (2) causal/DAG confounder adjustment (replace association with causation so the edge transports across regimes), and (3) a Deflated-Sharpe governor (deflate selection bias). These became the backbone of everything after.

Honest ordering

Not "LdP is universally best." Rather: meta-labeling (1) coincides with the F1 target (size overlay) and has the most direct evidence → first. The DSR governor (3) is non-negotiable infrastructure, deployed in parallel. Causal (2) is the deepest but most speculative → deferred. This separation of "additive vs protective vs transport" was itself a lesson (see F7).
F3 — DiagnoseMeasure on real data before building anythingconditional performance dictates features & barriers
Reusable principle

Let the instrument's own history pick your features and parameters

Before writing the overlay, profile when the primary edge works and when it breaks (non-stationarity + conditional buckets), and let per-trade excursions (MFE/MAE) set barrier geometry. Calibrate in the instrument's native units — a unit error here silently corrupts everything downstream.
Decision gate: what single conditioning variable separates good days from bad, and in what units must barriers be set?
Case study — ZN: Efficiency Ratio is king; edge decays post-2003
Conditional Sharpe by Kaufman Efficiency Ratio tercile (martin_primary_ema2 @ US10, strategy-pct). ER dominates (spread 5.64 / 4.35). Counter-intuitively, speed-disagreement days scored highest (+4.12) — prior assumption discarded; let the model learn the sign.

Non-stationarity found

Decade Sharpe 1980s 0.51 → 2010s 0.11 → 2020s 0.37; CUSUM break 2003-06-13 with post-break Sharpe collapsing to 0.019. Daily skew flips sign (negative pre-2000s → positive after). Standalone EMA2 is essentially flat post-2003 — a warning the overlay could not erase.

Barriers, calibrated on RAW σ (the unit trap, pre-empted)

Per-trade MFE/MAE → asymmetric barriers PT 8σSL 4σT_max 120d. Crucially these are in raw price-point σ (median 0.39), not vol-targeted strategy-%. An earlier strategy-% reading had implied ~3σ/1.5σ — off by ~3× in scale. Verified later: ZN σ reproduced at 0.3871.
F4 — GovernBuild the experiment-registry & anti-overfitting machinery before the result existsso the result cannot bias the bar
Reusable principle

A family layer that answers "what's next?" and a governor that rises every time you test

Organize experiments as a family matrix (3-tier dimensions: universe / spec / execution), separate single-instrument from portfolio panels, and record an elasticity ledger (which axis moves performance — by axis, with honest n_pairs, not by cell). Pair it with a Deflated-Sharpe governor whose threshold rises with the true number of configs searched. Registering an experiment makes the future bar harder.
Decision gate: is n_configs counted honestly (internal sweeps included), and is the DSR formula complete (skew/kurtosis + Euler-Mascheroni)?
Case study — the self-correcting loop, observed firing
Locking the TBM pre-reg raised the family DSR threshold 0.314 → 0.325 (N 41→50), which retroactively stripped two existing cells of absolute-promotion status. Cherry-picking is structurally blocked: the act of testing more raises the hurdle for everything.

Three review rounds, three real corrections

  • Instrument made a 1st-class dimension — so single→multi expands by appending rows, not cloning the family.
  • n_configs split from n_cells — DSR uses the honest upper-bound config count (incl. internal sweeps), not the count of registry entries.
  • Elasticity downgraded to "direction-only, n_pairs shown" — the prior "rule_structure is active" claim was confounded (it also varied execution profile); recorded as such rather than asserted.

Why before results

Governance built while the outcome was still unknown is the only governance that can't be reverse-engineered to bless a favored result. This ordering is the point.
F5 — Build & red-teamImplement as a thin overlay; catch the statistical traps before the first runside fixed · size learned · skew preserved
Reusable principle

Attach, don't rebuild. Then adversarially review the pipeline for selection & leakage

Implement the overlay as a label-only attachment on the existing engine (consume the primary's sign; learn only size). Before running, red-team for the classic failures: in-sample config selection that bypasses the deflation, evaluation thresholds that double-count a parameter, and look-ahead across data gaps.
Decision gate: does best-config selection sneak past the DSR? does the size map keep the skew constraint? are gaps handled at the right pipeline stage?
Case study — three traps caught, plus a clarified design choice
Pre-run review caught three statistical traps that would each have produced a falsely-favorable or corrupted result. A fourth item — the semantics of how size attaches to side — was resolved by understanding that CUSUM is a sampling tool, not an entry signal.

The skew guardrail, by construction

Size map g(m) = 0.30 + 0.70·clip((m−τ)/(1−τ)) ⇒ g ∈ [0.30, 1.0], always ≥ 0. The effective weight on Martin's momentum never goes negative, so the positive-skew style constraint (Eq. 20) is preserved by construction — the engine is untouched; only the throttle is learned.

CUSUM = sampling, not entry (the Y-daily resolution)

The session paused to settle a genuine ambiguity: since side is daily (continuous Martin) but CUSUM events are sparse, "what is g between events?" The resolution: train on CUSUM-day labels (clean, less-overlapping), but predict g every day from daily features (ER changes daily; the throttle must too). Verified no train/infer bias (|Δmean g| = 0.001).
F6 — Run & adjudicateRead the result for effect size, not gate color; isolate cause with one ablation"timid model" vs "no signal" — decide it
Reusable principle

Passing gates is not success — interrogate the magnitude, then run one decisive ablation

A relative gate can pass while the overlay does almost nothing. Read the effect size (here: the distribution of the learned size g). When a result is ambiguous, design a single-variable ablation that discriminates between competing explanations — don't sweep blindly (every sweep raises the DSR bar).
Decision gate: is the gain real or is the model just de-leveraging? what one change separates the hypotheses?
Case study — the ablation that returned a clean "no signal"
Hypothesis: g stuck near the 0.30 floor because of effective-sample collapse (T_max=120 overlaps labels heavily, eff. sample ~290). Test: cut T_max to 40 (eff. sample ~410). Result: g-max moved only 0.551→0.591. Sample recovery did not free the model → the limit is signal, not timidity.

F7 — CompoundWrite the lessons as reusable rules; close the loop so the next strategy is fasterthe process is the product
Reusable principle

Every session deposits two durable assets: a refined process and a lessons ledger

The strategy may fail; the process and lessons must not be lost to a closed session. Persist them as files (the AI-native premise: state lives on disk, sessions are disposable). Each lesson is phrased as a rule for next time, so productivity compounds rather than resets.
L1
Units are a load-bearing decision — declare them at schema level
Strategy-% vs raw price-σ differed by ~3× and nearly mis-scaled the barriers; the same trap reappeared in the DSR (per-period vs annualized). Rule: every metric carries an explicit unit tag; verify on real data (σ=0.3871) before building.
L2
A single instrument has an effective-sample ceiling
4143 nominal labels → ~290–410 effective (avg-uniqueness 0.07–0.10) because of overlap; the meta-model could not escape the floor. Rule: for overlay learning, secure breadth (multi-instrument / pseudo-cross-section) before expecting conditional alpha.
L3
In-sample best-config selection silently bypasses deflation
Picking the top-Sharpe config and then deflating with N is selection counted once but applied twice. Rule: lock a single pre-registered config, or select inside nested CV; never argmax then deflate.
L4
Build the governor before the result; let testing raise its own bar
The DSR threshold rose 0.314→0.325 on registering TBM and retroactively de-promoted two cells. Rule: n_configs counted honestly (internal sweeps included); registration is a cost that protects against data-snooping.
L5
Gates passing ≠ value added — read effect size, then ablate to find cause
5/5 relative gates passed while g sat at its floor. One T_max ablation separated "timid model" from "no signal." Rule: interrogate magnitude; discriminate with a single variable, not a blind sweep.
L6
Know which layer a method lives on before composing
sMOM (Hanauer–Windmüller) is a size overlay on cross-sectional momentum — same layer as TBM (competition, not complement) and natively multi-instrument. Rule: classify side/size and cross-sectional/time-series before stacking overlays; don't multiply two size-scalers.
L7
Separate additive vs protective vs transport work — and sequence accordingly
Meta-labeling (additive) first; DSR governor (protective) in parallel; causal/transport (deepest, most speculative) last. Rule: don't let a protective tool masquerade as alpha, and don't lead with the highest-variance bet.

Why this is AI-native, not just "AI-assisted." The loop assumes sessions are disposable and state lives in files (family.yaml, findings.md, the lessons ledger, pre-regs). A human supplies formulas and parameters and makes the irreducible judgment calls; the AI executes, red-teams its own pipeline, and surfaces the next-highest-information action from the ledger. Productivity compounds because the bar rises (DSR) while the starting point advances (lessons) — the same negative result that ended this case study is, on the next instrument, a step already taken.
